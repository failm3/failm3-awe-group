# Доступ к Telegram: подтверждённые ограничения

Проверено 12.11.2026. Метод `messages.getHistory` возвращает историю от новых сообщений к старым и доступен только пользовательским аккаунтам, не ботам. Telegram отдельно документирует ошибки приватного или недоступного канала. Доступную публичную web-историю нельзя считать доказательством полноты истории API. [1]

Bot API используется для получения новых разрешённых обновлений и управления. Telegram хранит неполученные обновления не дольше 24 часов; это не API произвольной архивной истории чужих каналов. [2]

Для полной доступной истории нужен отдельный аккаунт владельца, собственные `api_id` и `api_hash`, полученные через `my.telegram.org/apps`, и соблюдение Telegram API Terms. Нельзя обходить ограничения, использовать опубликованный чужой API ID или обещать отсутствие риска блокировки: Telegram контролирует неофициальных клиентов. [3]

## Подключение на согласованном хосте

Создайте отдельную директорию секретов с правами 700 вне Git. Введите `API_ID` и `API_HASH` только в локальный secret store или файл с правами 600. Запустите интерактивную авторизацию подготовленного сборщика и вводите номер, код и при необходимости пароль двухфакторной защиты непосредственно в терминале хоста. Session-файл позволяет доступ к аккаунту: его нельзя пересылать в отчётах или коммитить. Рекомендуется отдельный аккаунт с доступом только к необходимым публичным источникам.

Команда авторизации и переменные конкретного адаптера описаны в документации сборщика после интеграции. До реального входа API-режим считается подготовленным, но не испытанным. Удалённые сообщения, недоступные медиа и частично скрытые материалы нельзя восстановить обещанием полной выгрузки; они фиксируются как ограничения.
